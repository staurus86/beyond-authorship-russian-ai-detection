# Амендмент: два варианта inner CV в P2a, clf-v2

Зарегистрировано 2026-07-29 **до запуска любого варианта серии v2**. Решение PI от той же даты. Запись в `amendments.md` вносит PI; этот документ — её содержание.

## 1. Что обнаружено

Перенос inner-разбиений P2a (`p2a-inner-carry.md`, решение PI от 2026-07-29) добавил в `clf_run.pick_c` проверку: validation каждого inner fold обязан содержать оба класса. На первом же прогоне `clf-v2` она остановила расчёт.

Разбор показал, что дефект принадлежит дизайну v1, а не коррекции корпуса. Семь inner fold-ов из 54 (18 holdout × 3) содержат в validation один класс, и состав этих fold-ов совпадает до и после исключения 34 документов.

| Holdout | Fold | Документов A | Документов H | Было в v1 |
|---|---|---|---|---|
| `holdout_genre_news` | 0 | 539 | 0 | A=539, H=0 |
| `holdout_genre_prose` | 0 | 539 | 0 | A=539, H=0 |
| `holdout_genre_science` | 0 | 539 | 0 | A=539, H=0 |
| `holdout_genre_seo` | 0 | 359 | 0 | A=359, H=0 |
| `holdout_genre_translation` | 0 | 539 | 0 | A=539, H=0 |
| `holdout_time` | 0 | 539 | 0 | A=539, H=0 |
| `holdout_source` | 2 | 0 | 289 | A=0, H=294 |

В clf-v1 такой fold пропускался строкой `continue` внутри `pick_c` — без записи в метрики, манифест и отчёт. Гиперпараметр в этих семи holdout выбирался по двум fold-ам из трёх, а заявлен был трёхкратный вложенный CV. Само число два нигде не публиковалось.

## 2. Решение

Считаются **два варианта P2a**, оба зарегистрированы здесь до расчёта. Выбор «лучшего по результату» запрещён: варианты отвечают на разные вопросы.

### A. `clf-v2-legacy` — мост к замороженному прогону

Полностью воспроизводит поведение v1:

- inner fold-ы берутся перенесёнными (`p2a-inner-folds-carried.json`);
- семь одноклассовых validation пропускаются;
- у затронутых holdout C выбирается по двум fold-ам;
- число фактически использованных fold-ов и список пропущенных пишутся в метрики и манифест.

Единственное назначение варианта — сравнение `clf-v1 → clf-v2-legacy`, то есть вклад очистки корпуса при неизменном алгоритме.

### B. `clf-v2-valid` — основной результат P2a

Для семи затронутых holdout строится новое замороженное grouped-разбиение. Требования, зафиксированные до построения:

- каждый validation содержит оба класса;
- группировка сохраняется — `split_group_source`, у машинных документов канал генерации;
- каждая train-группа попадает в validation ровно один раз;
- сетка C, метрика отбора, импутация и остальной pipeline не меняются;
- у остальных одиннадцати holdout распределение остаётся перенесённым.

**Правило построения.** Группы класса A сортируются по убыванию числа документов, при равенстве — по имени, и раскладываются по fold-ам по кругу. Группы класса H раскладываются так же и независимо. Правило детерминировано и не смотрит на зависимую переменную: оно использует только состав групп.

**Число fold-ов.** Три валидных fold-а возможны тогда и только тогда, когда в обучающей части не меньше трёх групп каждого класса. Проверка выполнена до расчёта метрик:

| Holdout | Групп A | Групп H | Fold-ов |
|---|---|---|---|
| `holdout_genre_news` | 4 | 21 | 3 |
| `holdout_genre_prose` | 4 | 18 | 3 |
| `holdout_genre_science` | 4 | 21 | 3 |
| `holdout_genre_seo` | 4 | 3 | 3 |
| `holdout_genre_translation` | 4 | 21 | 3 |
| `holdout_time` | 4 | 19 | 3 |
| `holdout_source` | 2 | 16 | **2** |

У `holdout_source` в обучающей части остаётся два машинных канала: третий fold без машинных документов получить нельзя при любой раскладке. Причина записана здесь, до расчёта метрик.

`clf-v2-valid` становится основным результатом P2a и источником для fairness-аудита, разбора ошибок, калибровки и раздела P2a в статье. `clf-v2-legacy` остаётся sensitivity.

## 3. Что сравнивается

Три сравнения публикуются вместе, без выбора варианта по результату:

1. `clf-v1 → clf-v2-legacy` — вклад коррекции корпуса;
2. `clf-v2-legacy → clf-v2-valid` — вклад исправления inner CV;
3. число holdout, у которых сменился выбранный C.

По каждому сравнению приводятся out-of-fold метрики основной модели и FPR на подгруппах hard-human.

## 4. Чего амендмент не делает

Внешние разбиения не трогаются: holdout-раскладка остаётся перенесённой из v1 (`splits-v5-carry.md`), P2b сохраняет свои перенесённые внешние и внутренние fold-ы (`inner-folds-carry.md`), где все двенадцать validation двухклассовы (`inner-cv-audit-v5.md`).

Задним числом clf-v1 не пересчитывается. Замороженный прогон остаётся как есть; его ограничение — подбор C по двум fold-ам из трёх в семи holdout — публикуется в разделе ограничений.
