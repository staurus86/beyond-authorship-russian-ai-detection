# План управления данными

## 1. Что собирается

| Тип | Источник | Объём | Персональные данные |
|---|---|---|---|
| Человеческие тексты (core) | 30+ авторов по заданиям | 120 | да, отдельно от текстов |
| Внешний hard-human | открытые источники, архивы, документация | 300–500 | обычно нет, проверять |
| Машинные тексты | API четырёх семейств моделей | 960–1440 | нет |
| Гибриды A→H, H→A | редакторы, модели | 240+ | да, по редакторам |
| Разметка | 3+ разметчика | 300–450 документов × 3 | псевдонимы рейтеров |
| Метаданные генерации | логи API | по числу генераций | нет |

## 2. Хранение

```
04-corpus/
  raw-*/            неизменяемые исходники, только добавление
  derived/          нормализованные версии, пересоздаваемые скриптом
00-admin/private/   персональные данные, вне репозитория и вне публикации
```

Правила:

- сырой файл после приёмки не редактируется — исправления оформляются новой версией с новым `document_id` и записью в `revision_family_id`;
- каждый файл получает SHA-256, хеши лежат в `04-corpus/hashes.csv`;
- нормализация (пробелы, кавычки, переносы) применяется только к производным версиям и описана в `06-features/preprocessing-spec.md`;
- персональные данные не попадают в каталоги корпуса ни в каком виде.

## 3. Именование

`{origin}_{genre}_{brief}_{source}_{seq}`

Пример: `ai_seo_b012_gptfamily_r2`, `human_analytics_b031_a07_r1`.

Расшифровка полей — `04-corpus/README.md`. Имя файла не должно раскрывать происхождение разметчику: при выгрузке батча файлы переименовываются в случайные идентификаторы, соответствие хранится в `05-annotation/blinding-map.csv` вне доступа разметчиков.

## 4. Резервные копии

- рабочая копия на машине исследователя;
- версионируемая копия (git или аналог) для всего, кроме `private/`;
- внешняя копия раз в неделю на время активного сбора.

Проверка восстановления — раз в месяц, отметка в `corpus-changelog.md`.

## 5. Что публикуется

| Компонент | Публикация | Условие |
|---|---|---|
| Машинные тексты | да | политика поставщика модели допускает |
| Человеческие тексты core | да | согласие автора, пункт 3 формы |
| Hard-human из открытых источников | ссылками, не копиями | лицензия источника |
| Гибриды | да | согласие редактора |
| Разметка | да | псевдонимизированная |
| Признаки и скрипты | да | всегда |
| Персональные данные | нет | никогда |

Спорные случаи по лицензиям решаются до сбора, а не после. Текст без ясного правового статуса в корпус не включается.

## 6. Сроки хранения

Персональные данные — до публикации статьи плюс [срок], затем удаление. Корпус и признаки — бессрочно.

## 7. Ответственность

Ведёт principal investigator. Каждое изменение состава корпуса фиксируется в `corpus-changelog.md` с датой и причиной.
