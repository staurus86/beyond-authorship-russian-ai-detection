# Разбиение данных

## Запрещено

Случайно перемешать документы и разделить 80/20. При таком разбиении модель видит в обучении: тот же промпт, ту же тему, другую версию того же текста, тексты того же автора, тот же машинный шаблон. Результат завышается и не переносится никуда.

## Восемь обязательных holdout

| # | Holdout | Что исключается из train | Что проверяет |
|---|---|---|---|
| 1 | Тема | темы тестового набора | не выучил ли классификатор предметную лексику |
| 2 | Автор | все тексты автора | не выучил ли индивидуальный стиль |
| 3 | Модель | одно семейство целиком | перенос на неизвестный генератор |
| 4 | Промпт | один prompt condition | перенос на другую формулировку задания |
| 5 | Жанр | один жанр целиком | перенос между типами текста |
| 6 | Revision family | все версии одного текста только в одном split | утечка через редактуру и рерайт |
| 7 | Внешние человеческие источники | hard-human не участвует в обучении вообще | честный FPR |
| 8 | Время | тексты и генераторы, собранные после заморозки модели | устаревание маркеров |

## Source-disjoint holdout: состояние и ограничение

Внесено 2026-07-24 по внешней рецензии.

**Правило.** Обучающая и тестовая части не делят источник. Документ одного издания, репозитория или коллекции целиком лежит по одну сторону разбиения. Случайные эффекты `source_id` и `author_id`, где авторство известно, входят в модель. Доверительные интервалы считаются cluster bootstrap по источникам.

**Чем это ограничено сейчас.** Разнообразие источников по стратам:

| Страта | Документов | Источников |
|---|---|---|
| 0 свободные | 120 | **2** |
| 1 публицистика | 120 | **2** |
| 2 шаблонные | 181 | 9 |
| 3 стандартизованная проза | 108 | **2** |
| hard-human, переводы | 73 | **1** |

Три страты из четырёх стоят на двух источниках. Отложить один — значит обучаться на единственном оставшемся, и тогда диагностический baseline «только источник» почти наверняка сравняется с основной моделью. По §10 preregistration это прямо означает скомпрометированный дизайн.

**Что из этого следует.**

1. До добора источников source-disjoint holdout выполним полноценно только на страте 2.
2. Для страт 0, 1, 3 и hard-human публикуется прямая оговорка: holdout по источнику ограничен, результаты классификатора на этих стратах читаются с поправкой на возможную утечку источника.
3. Диагностический baseline «только источник» считается по каждой страте отдельно и публикуется всегда, включая случаи, где он неудобен.
4. Добор источников — задача этапа 6, приоритет выше выравнивания численности страт.

**Почему добор важнее выравнивания.** Дисбаланс 181 против 108 — вопрос весов. Два источника на страту — вопрос того, измеряем ли мы стиль или коллекцию. Сто восемьдесят один документ из девяти источников несёт больше независимой информации, чем сто восемь из двух.

## Отчётные срезы

Основной отчёт содержит минимум шесть настроек:

1. in-domain;
2. неизвестная модель;
3. неизвестный prompt condition;
4. неизвестный жанр;
5. гибридные и отредактированные тексты;
6. hard-human.

Средняя цифра без срезов результатом не считается.

## Группировка

Поля реестра, которые определяют группу: `split_group_author`, `split_group_source`, `split_group_topic`, `revision_family_id`, `leakage_group`, `dedup_cluster_id`.

Правило: все узлы одного provenance graph попадают в один split. Цепочка `человеческий текст → машинная редактура → повторная правка` не разрывается между train и test ни при каких условиях.

## Манифесты

Каждое разбиение сохраняется как манифест: список `document_id` по split, сид, дата, версия реестра, хеш. Без манифеста результат не воспроизводится и в статью не идёт.

Файл: `splits/{split_name}_{date}.json`.

## Проверка перед обучением

- [ ] пересечение document_id между split пусто
- [ ] пересечение по группам (автор, тема, источник, revision family) пусто
- [ ] дубликаты и почти-дубликаты в одном split
- [ ] распределение классов по split описано
- [ ] hard-human не участвует в обучении
- [ ] baseline «только тема» и «только источник» посчитаны на том же разбиении
