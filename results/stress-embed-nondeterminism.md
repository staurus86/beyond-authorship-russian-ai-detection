# Недетерминизм эмбеддингов в стресс-панели

Дата: 2026-07-30. Обнаружен при диагностике нарушения sentinel-инварианта
`applied_no_change` у `human_science_cyberleninka_0032`.

## Что обнаружено

Из 50 групп «один документ + один и тот же `prose_sha` в разных ячейках» массивы
эмбеддингов BGE-M3 различаются у **43**. Значение M05 дрожит примерно в 7–8 знаке
от запуска к запуску при полностью совпадающем входе.

## Механизм

`embed_stage` (`stress_run_p1.py:217-244`) кодирует предложения несколькими вызовами
`model.encode()`. Набор текстов в каждой порции определяется порядком обхода
`sorted(st.TRANSFORMS) × sorted(rows)` и константой `_EMBED_FLUSH_AT`. Один и тот
же текст попадает в разные порции в зависимости от того, какие другие тексты оказались
рядом в очереди.

Два источника вариации в `model.encode()`:
1. **Padding:** `sentence-transformers` группирует тексты по длине внутри батча.
   Разный состав батча → разный padding → иная маска → субпиксельное расхождение в
   matmul на float32.
2. **Порядок редукции при 16 потоках:** PyTorch сворачивает параллельные
   accumulate-операции в нефиксированном порядке, что даёт разные результаты при
   разном размере батча.

Прямое подтверждение: изолированный пересчёт без кеша, одни и те же 45 предложений:

| вариант | сумма матрицы | M05 | перцентиль M05 |
|---|---|---|---|
| кеш t02 | −33.6575660706 | 0.066806852818 | 0.6646706586826348 |
| кеш t16 | −33.6575622559 | 0.066807031631 | 0.6706586826347305 |
| пересчёт batch_size=64 | −33.6575622559 | 0.066807150841 | 0.6706586826347305 |
| пересчёт batch_size=32 | −33.6575660706 | 0.066806972027 | 0.6706586826347305 |
| пересчёт batch_size=8 | −33.6575660706 | 0.066806972027 | 0.6706586826347305 |
| пересчёт batch_size=1 | −33.6575622559 | 0.066806912422 | 0.6706586826347305 |
| в пачке с +69 чужих | −33.6575660706 | 0.066807031631 | 0.6706586826347305 |

Все варианты, кроме кеша t02, дают перцентиль 0.6706586826347305. Кеш t02 —
единственный, кто попал ниже границы.

## Почему это привело к скачку индекса

`M05` — признак категории `Information-theoretic`, направление `down`. `tercile_score`
даёт 0.5 при перцентиле < 2/3 и 0.0 при перцентиле ≥ 2/3. Граница 2/3 равна
0.666666...; перцентиль t02 = 0.66467 < 2/3 (балл 0.5), перцентиль t16 = 0.67066 ≥ 2/3
(балл 0.0). Поэтому:

```
Δ средней категории = (0.0 - 0.5) / 2 = -0.25
Δ common = 0.1 × (-0.25) / 0.57 × 100 = -4.385965
Δ индекса = -4.385965 × 0.57 / 0.69 = -3.6232
```

Наблюдённое расхождение 33.9372 − 37.5604 = −3.6232. Совпадение точное.

## Масштаб

Из 50 групп «один документ + один `prose_sha`» у 43 эмбеддинги различаются.

Ячейки, где перцентиль M01/M02/M05 стоит ближе одного шага ранга от границы терциля
(проверка `diag_risk.py`, 2026-07-30):

| признак | проверено ячеек | у границы (< 1 шага ранга) |
|---|---|---|
| M01 | 654 | 9 |
| M02 | 545 | 10 |
| M05 | 654 | 11 |
| всего | 1853 | 30 (1.6%) |

9 ячеек стоят ровно на перцентиле 1/3 или 2/3 (`0.333333` / `0.666667`). Они
переходят терциль при любом субпиксельном дрейфе в любую сторону. Остальные 21 —
в пределах одного шага ранга.

## Ключевые следствия

**Sentinel-инвариант у 43 ячеек панели нарушен из-за недетерминизма, а не из-за
смены текста.** Ослаблять допуск нельзя: инвариант поймал дефект расчёта FORMAT.
Два дефекта действуют параллельно: FORMAT-нули (352 ячейки, 32 документа) и
эмбеддинговый дрейф (≥43 ячейки, охват уточняется).

**Один кеш — один прогон.** Этап `embed` уже однажды запущен (шаг 1, 60.1 мин).
Кеш содержит 660 записей, каждая с конкретным sub-pixel значением. При пересчёте
FORMAT по пути 1 придётся решить: оставить кеш как есть (аналитический нонс) или
пересчитать (стоит ещё ~60 мин, дрейф сохранится, только перераспределится между
ячейками). Оставить кеш — детерминированный прогон в рамках данной ревизии;
пересчитать — получить другой случайный набор значений.

**Кеш t02 как аномалия.** Это единственный вариант с перцентилем M05 ниже 2/3.
Пересчёт без кеша не воспроизвёл его ни при каком `batch_size`. Причина — состав
батча при первом запуске этапа embed, документировать который постфактум невозможно.

## Решение PI 2026-07-30

Кеш не признаётся достаточным. Формулировка решения: кеш делает конкретный
артефакт повторяемым, но не делает процедуру воспроизводимой; 43 группы из 50 с
одинаковым входом и разными массивами — это провал инварианта «одинаковый вход →
одинаковый результат», а дискретизация M05 усиливает погрешность float32 до
содержательного скачка.

`stress-embed-v1` сохраняется как инвалидированный диагностический артефакт: на
нём измерен дрейф, без него замер невоспроизводим. Расчёт переносится в ревизию
r3 с новым кешем `stress-embed-v2` — `amendment-stress-r3-pipeline.md`.

**Найденный корень.** Недетерминизм давала не многопоточность, а состав батча:
`flush()` копил до 512 предложений разных документов, и один и тот же текст
попадал в разные батчи в зависимости от порядка обхода панели. В r3 каждый
уникальный вход кодируется отдельным вызовом `encode`, поэтому состав батча задан
самим входом.

Замер трёх режимов, по два независимых процесса на каждый:

| Режим | sha прогона A | sha прогона B | Оценка на 720 входов |
|---|---|---|---|
| 1 поток, батч 1 | `1e1ca288a4ae1d31` | `1e1ca288a4ae1d31` | 277 и 272 мин |
| 1 поток, батч 64 | `83410fa4d38d65ac` | `83410fa4d38d65ac` | 393 и 1044 мин |
| 16 потоков, батч 64 | `ae54edd1a5d3c05c` | `ae54edd1a5d3c05c` | 360 и 358 мин |

Побитово повторяемы все три, но значения между режимами не совпадают, поэтому
режим фиксируется и входит в строку ревизии кеша. Выбран `1 поток, батч 1`: при
батче 1 нет паддинга, поэтому он ещё и быстрее остальных.

## Что остаётся ограничением

Чувствительность самой шкалы: `tercile_score` переводит перцентиль в 0, 0.5 или 1
по границам 1/3 и 2/3, поэтому малое изменение входа может дать дискретный скачок
индекса, непропорциональный величине изменения текста. Из 1853 проверок M01, M02
и M05 по панели 30 (1.6%) стоят ближе одного шага ранга от границы, 9 — ровно на
границе. В r3 это не мешает воспроизводимости: режим детерминирован, повторный
прогон даёт те же значения.

Диагностика `human_science_cyberleninka_0032` — свойство численной процедуры, а
не результат текстового стресс-теста, и в его показатели не входит.

## Команды для воспроизведения

```python
# проверить, что эмбеддинги t02 и t16 различаются
import hashlib, numpy as np, sys
sys.path.insert(0, '09-tools')
from pathlib import Path
import feature_cache as fc, extract_features as ef, stress_run_p1 as srp

ROOT = Path(r"<PROJECT_ROOT>")
EMBED = ROOT / "06-features" / "cache" / "stress-embed-v1"
TEXTS = ROOT / "04-corpus" / "derived" / "stress-v1"
DOC = "human_science_cyberleninka_0032"

sha = fc.sha256_file(TEXTS / "t02" / "prose" / f"{DOC}.txt")
for cell in ("t02", "t16"):
    e = fc.lookup(EMBED, fc.load_index(EMBED), f"{cell}:{DOC}", sha, srp._EMBED_REVISION)
    with np.load(e) as pl: v = pl["embeddings"]
    print(cell, hashlib.sha256(v.tobytes()).hexdigest()[:16], "сумма", v.sum())
```
