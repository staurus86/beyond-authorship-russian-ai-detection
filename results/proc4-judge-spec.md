# Процедура 4: модель-судья (judge-v1)

Статус — **exploratory**. Операционализация пишется 2026-07-27, после просмотра результатов процедуры 1.

§7 preregistration задаёт: «медиана трёх прогонов, отдельная запись разброса». Всё остальное фиксируется здесь, до первого вызова.

## 1. Судья: локальный артефакт `gemma3:12b-it-qat`

**Требование, вытекающее из §13 preregistration:** судья не должен принадлежать семейству, породившему корпус. Каналы генерации — `claude-opus-4-8`, `gpt-5.5`, `deepseek-v4-pro`, `nemotron-3-ultra`; все четыре исключены.

**История блокировки.** 27 июля проверка через `http://localhost:11434/api/tags` показала три установленные модели, и ни одна не проходила §1.1: `gpt-oss:120b-cloud` (384 байта) и `kimi-k2.5:cloud` (340 байт) несут `remote_host: https://ollama.com:443`, то есть ссылку на облако вместо весов; `qwen2.5-coder:7b` специализирована под код. Прежняя редакция утверждала, что `gpt-oss` работает локально — это было неверно: обращение к любой из двух cloud-моделей означает отправку текстов на `ollama.com`, внешнюю передачу материала, часть которого собрана по лицензиям с ограничениями и по согласиям участников.

**Запрет на внешнюю передачу остаётся в силе.** Cloud-модели не используются ни в каком варианте процедуры.

**Блокировка снята 2026-07-28 установкой локального артефакта.** Амендмент от той же даты. Проверка по пяти критериям §1.1 выполнена запросами до подачи первого текста корпуса:

| Критерий | Проверка | Результат |
|---|---|---|
| 1. веса на машине | `/api/tags` | `remote_host` отсутствует; 8 928 675 346 байт, gguf, Q4_0 |
| 2. не из семейств корпуса | реестр каналов | семейство `gemma3`, ни одного пересечения с четырьмя каналами |
| 3. общего назначения | `/api/show` | `capabilities: completion, vision`, 12 187 079 280 параметров |
| 4. русский язык | три внешних текста вне корпуса | ответы на русском, JSON валиден трижды, порядок оценок ожидаемый |
| 5. контекст | `/api/show`, `/api/ps` | `context_length` 131 072, рабочий `num_ctx` 16 384, модель целиком в VRAM |

Фактическую длину самого длинного документа в токенах судьи меряет preflight: оценка 11 532 токена посчитана для токенизатора `rugpt3` и на `gemma3` не переносится.

**Переключение модели внутри прогона запрещено.** Резервной модели у процедуры нет: при недоступности выбранного артефакта процедура останавливается, вносится амендмент, спецификация перехешируется, и только потом расчёт запускается заново.

### 1.1. Критерии пригодности судьи

Задаются здесь, до выбора модели. Модель, удовлетворяющая всем пяти, годится; выбор среди годных делается по факту доступности локального артефакта, а не по результатам оценки.

1. веса лежат на машине — в `/api/tags` отсутствует `remote_host`, размер соответствует весам, а не манифесту;
2. модель не принадлежит семействам, породившим корпус: `claude-opus-4-8`, `gpt-5.5`, `deepseek-v4-pro`, `nemotron-3-ultra`;
3. модель общего назначения, а не специализированная под код или иную узкую задачу;
4. поддерживает русский язык — проверяется на внешних тестовых текстах, не входящих в корпус;
5. фактический `context_length` из `/api/show` вмещает промпт и самый длинный документ корпуса — 11 532 токена по оценке preflight.

**Что фиксируется в манифесте после получения локального артефакта — до первого текста:**

| Параметр | Источник | Значение на 2026-07-28 |
|---|---|---|
| точный тег, не `latest` | команда установки | `gemma3:12b-it-qat` |
| digest модели | `/api/tags` | `5d4fa005e7bb5931be8bc35224080a9b316c7e1c069c9481a6a51b607f4252e2` |
| версия ollama | `/api/version` | 0.18.0 |
| quantization_level | `/api/show` | Q4_0 |
| template | `/api/show` | записывается в манифест дословно |
| `num_ctx` | параметры вызова | 16 384 |
| reasoning effort | параметры вызова | не применяется: у `gemma3` режима рассуждения нет |
| полный набор sampling options | параметры вызова и `/api/show` | §3 |
| JSON schema ответа | §2 | `{"score": integer 0–100, "reason": string}`, обязательны оба поля |
| максимальный размер вывода | параметры вызова | `num_predict` = 200 |

## 2. Промпт

Задаётся дословно и не меняется между прогонами:

```
Ты оцениваешь стилевые признаки текста.

Оцени, насколько выражены в тексте признаки шаблонного, машинно-порождённого
стиля: равномерность синтаксиса, отсутствие вариативности длины предложений,
ритуальные оговорки, симметричные конструкции, обобщённые формулировки без
конкретики.

Шкала 0-100:
0-20   — признаки почти не выражены
21-40  — выражены слабо
41-60  — выражены умеренно
61-80  — выражены заметно
81-100 — выражены сильно

Оценивай только стиль. Не пытайся угадать, кто написал текст.

Ответь строго в формате JSON, без пояснений:
{"score": <целое число 0-100>, "reason": "<одно предложение>"}

Текст:
<<<TEXT>>>
```

**Что в промпт не попадает:** имя файла, идентификатор документа, название канала или модели, режим задания, жанр, источник, происхождение. Судья видит только текст профиля `prose`.

**Направление шкалы:** выше — сильнее выражены признаки шаблонного стиля. Зафиксировано здесь и после расчёта не меняется.

Шкала измеряет **выраженность стилевых признаков**, а не вероятность машинного происхождения. Перевод в вероятность запрещён, пороги вида «выше 60 — машина» не применяются.

## 3. Параметры вызова

| Параметр | Значение | Основание |
|---|---|---|
| температура | **1.0** | §3.1 — три вызова должны быть стохастическими повторами |
| top_p | **1.0** | там же |
| top_k | 64 | значение по умолчанию артефакта из `/api/show`, не переопределяется |
| num_ctx | 16 384 | §1, критерий 5 |
| num_predict | 200 | ответ — одно число и одно предложение |
| число независимых вызовов на документ | 3 | §7 preregistration |
| seed | 20260727, 20260728, 20260729 | по одному на вызов |
| формат ответа | JSON по схеме, передаётся в поле `format` запроса | §2 |
| итоговая оценка | медиана трёх | §7 preregistration |

**Схема ответа передаётся движку, а не только просится в промпте.** Поле `format` запроса `/api/generate` несёт JSON Schema с обязательными `score` (целое 0–100) и `reason` (строка). Промпт §2 при этом не меняется: он остаётся дословно тем же и содержит то же требование формата.

**Почему не температура 0.** При нулевой температуре три вызова с разными seed проверяли бы детерминизм бэкенда, а не устойчивость судейской оценки: медиана трёх почти совпадающих чисел не несёт информации, а показатели согласия оказались бы завышены по построению. При температуре 1.0 три прогона дают три стохастических повтора, и медиана с ICC получают содержательный смысл — именно ту нестабильность, которую §7 требует записывать отдельно.

Остальные sampling options фиксируются в манифесте по фактическому ответу `/api/show` установленного артефакта.

## 4. Обработка сбоев

| Случай | Действие |
|---|---|
| невалидный JSON | вызов повторяется один раз с тем же seed; при повторной неудаче помечается `invalid` |
| `score` вне 0–100 | помечается `out_of_range`, в медиану не входит |
| отказ модели отвечать | помечается `refusal`, в медиану не входит |
| валидных оценок меньше двух | документ получает пропуск с причиной, оценка не выставляется |

Все сырые ответы сохраняются целиком в `07-analysis/judge-v1-raw.jsonl`, включая невалидные: без них показатели согласия непроверяемы.

## 5. Согласие трёх прогонов

**Медиана не должна скрывать нестабильность.** Публикуются обязательно:

- доля документов, где все три оценки совпали точно;
- средний размах трёх оценок, `max − min`;
- медианный размах;
- ICC(2,1) — двусторонняя случайная модель, единичная мера, по трём прогонам как «оценщикам»;
- доля документов с размахом свыше 20 пунктов шкалы.

Если средний размах превысит 20 пунктов, результат публикуется с пометкой о низкой воспроизводимости оценки судьи, а контрасты — с указанием, что шум измерения сопоставим с ожидаемым эффектом.

## 6. Estimands

**full операционализируется:** контрасты `P3 − P1` на 359 парах и `P2 − P1` на 360, кластеризация по 45 заданиям.

**net — `not available`.** Суждение модели о стиле не разлагается на структурную и нестилевую части: судья читает текст целиком, и удаление разметки изменило бы не только структурный вклад, но и связность, на которую он тоже реагирует. Имитация не создаётся.

## 7. Объём и его последствия

1916 документов × 3 вызова = 5748 запросов к локальной модели.

**Решение PI от 2026-07-28, принятое до первого вызова: считается весь корпус.** Зарегистрированная подвыборка — 719 документов пар O1 плюс 300 случайных человеческих, сид 20260727 — остаётся описанной здесь, но не применяется. Возврат к ней после просмотра результатов запрещён.

Замер на трёх внешних текстах дал 3.6–5.6 секунды на вызов после прогрева; ожидаемое время полного прогона — около восьми часов. Прогон идёт одной командой и не делится на части, результаты которых просматриваются по ходу.
