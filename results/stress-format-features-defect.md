# Дефект расчёта форматных признаков в стресс-панели

Дата: 2026-07-30. Обнаружен шлюзом завершения P1 на шаге 3 цепочки `stress_run_chain.py`.
Решение за PI, преобразования и панель не тронуты.

## Что обнаружено

Три признака из четырёх в категории FORMAT — `F01`, `R06`, `R07` — равны нулю у всех
660 ячеек стресс-панели. Живым остаётся только `P01`.

`score_style_index.py:70` задаёт категорию так:

```
FORMAT = {"Structural Markers": (0.12, {"F01": "up", "R06": "up", "R07": "up", "P01": "up"})}
```

То есть форматный компонент индекса в стресс-тесте держится на одном признаке из
четырёх, а три остальных вносят ноль независимо от документа и преобразования.

## Механизм

`extract_features.py:407-417` берёт эти три признака не из текста, а из манифеста
препроцессинга — колонок `full_bold_spans`, `heading_md`, `list_items`:

```python
value = float(manifest_row.get(column) or 0)
out[feature_id] = (name, value, value * scale, "на 1000 слов профиля full")
```

Стресс-тест собирает `manifest_row` вручную и передаёт четыре ключа —
`prose_words`, `full_words`, `full_path`, `prose_path` (`stress_run_p1.py:522-527`).
Нужных колонок в нём нет, поэтому `.get(column) or 0` возвращает ноль, а признак
получает значение 0.0 без ошибки и без предупреждения.

Тот же четырёхключевой словарь собирает `stress_run_p2.py:312-317`, поэтому шаги 6
и 7 цепочки унаследуют дефект. Процедуры P3 и P4 признаки не используют, их это не
касается.

Данные для расчёта на месте: `04-corpus/derived/prep-v5/manifest.csv` содержит 1882
строки и все три колонки. Они просто не доходят до экстрактора.

## Как дефект себя проявил

Шлюз P1 отверг прогон с формулировкой:

```
72 из 160 applied_no_change вне допуска 0.0001: max|Δ| = 13.043500
```

`applied_no_change` — sentinel-инвариант: если преобразование не изменило текст,
индекс обязан совпасть с baseline. Разбор 72 нарушений:

| Группа | Ячеек | Чем объясняется |
|---|---|---|
| `full` изменился, `prose` нет | 29 | форматные признаки меняются законно, инвариант проверяет только `prose_sha` (`stress_run_p1.py:610`) |
| `prose` и `full` побитово идентичны оригиналу | 43 | дефект нулевых признаков |

Всего ячеек с побитово идентичными профилями — 122, из них 79 прошли в допуске.
Прошли те, у которых значения признаков нулевые и в основном корпусе: ноль совпал
с нулём.

Величины расхождений подтверждают механизм арифметически. Признак весит
0.03 из 0.12, знаменатель индекса 0.69, поэтому потеря полного перцентиля одним
признаком даёт `100 × 0.03 / 0.69 = 4.3478`. Наблюдаемый максимум `13.0435` равен
ровно `3 × 4.3478` — три признака теряют полный перцентиль одновременно.
Промежуточное значение `2.1739` соответствует перепаду перцентиля на 0.5.

## Охват

Панель — 60 документов × 11 преобразований. По манифесту `prep-v5` ненулевое
значение хотя бы одного из трёх признаков имеют 32 документа из 60. Их форматный
компонент искажён во всех преобразованиях: 352 ячейки из 660. У остальных 28
документов значения нулевые и в корпусе, расхождения нет.

## Что причиной не является

Пересчёт признаков расходится с матрицей на 1e-7 … 1e-6 у всех документов —
это округление `feature-matrix-v5.csv` до шести значащих цифр (`%.6g`).
Тот же фон присутствует у контрольных ячеек с Δ = 0, на индекс он не влияет.

## Отдельный факт, механизмом не объяснённый

`human_science_cyberleninka_0032` при побитово идентичном входе получил два разных
индекса в разных преобразованиях: 33.9372 и 37.5604. Остальные 121 ячейка с
идентичным входом дают внутри документа одно значение. Причина не установлена,
разбор нужен отдельно: нулевые признаки объясняют расхождение с baseline, но не
расхождение между преобразованиями.

## Что это меняет в чтении t14

`stress-t14-defect.md` называет эффект t14 лексико-форматным и отмечает, что
формат весит больше. Основание этого вывода требует перепроверки: три форматных
признака из четырёх в прогоне были нулевыми, и структурные признаки `F01`, `R06`,
`R07` на схлопывание абзацев отреагировать не могли. Реагировал только `P01`.

## Развилки, требующие решения PI

1. **Передать три колонки из манифеста `prep-v5`.** Дешевле всего по коду, но
   значения относятся к исходному документу и не меняются под преобразованием.
   Форматный компонент станет константой, а эффект форматных преобразований —
   t02 «удаление markdown-разметки», t03 «удаление заголовков», t14 — исчезнет
   по построению. Sentinel-инвариант при этом пройдёт, и дефект станет невидимым.
2. **Считать три счётчика по преобразованному профилю `full`.** Содержательно
   верный путь: признак меряет то, что заявлено. `prep.py` считает эти счётчики
   при разборе исходного документа на блоки (`prep.py:306`, `499-506`),
   применимость той же логики к готовому тексту `full` нужно проверить, а не
   предполагать. Требует амендмента, новой ревизии стресс-панели и перепрогона
   шагов 3, 6, 7.
3. **Объявить FORMAT-компонент в стресс-панели невыполнимым** и считать по
   стресс-панели только COMMON. Знаменатель меняется с 0.69 на 0.57, результаты
   перестают быть сопоставимыми с основным прогоном по составу индекса.
   Требует амендмента.

Вариант «ослабить допуск sentinel-инварианта» не предлагается: инвариант поймал
настоящий дефект расчёта, а не шум.

## Как проверить заново

Нулевые признаки в пересчёте одной ячейки (проверено 2026-07-30, вывод под командой):

```python
import sys, gzip, json; sys.path.insert(0, '09-tools')
import feature_cache as fc, extract_features as ef
from pathlib import Path

d = 'deepseek_pro_b007_P3_r2'; key = 't02:' + d
pr = Path('04-corpus/derived/stress-v1/t02/prose') / f'{d}.txt'
fu = Path('04-corpus/derived/stress-v1/t02/full') / f'{d}.txt'
cache = Path('06-features/cache/stress-stanza-v1')
p = fc.lookup(cache, fc.load_index(cache), key, fc.sha256_file(pr), ef.STANZA_REVISION)
parsed = json.load(gzip.open(p, 'rt', encoding='utf-8'))
mr = {'prose_words': len(pr.read_text(encoding='utf-8').split()),
      'full_words': len(fu.read_text(encoding='utf-8').split())}
v, _ = ef.document_features(parsed, mr)
for f in ('F01', 'R06', 'R07', 'P01'):
    print(f, '->', v.get(f))
```

```
F01 -> ('Жирные фрагменты', 0.0, 0.0, 'на 1000 слов профиля full')
R06 -> ('Заголовки', 0.0, 0.0, 'на 1000 слов профиля full')
R07 -> ('Частота списков', 0.0, 0.0, 'на 1000 слов профиля full')
P01 -> ('Доля текста вне связной прозы', 0.03274853801169586, None, 'доля профиля full')
```

В матрице `feature-matrix-v5.csv` у этого документа `F01 = 5.84795`.
