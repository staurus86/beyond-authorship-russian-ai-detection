# Отбор нестабильных случаев instability-v1: спецификация

Составлено 2026-08-01 по решению PI, **до отбора конкретных ячеек**. Закрывает
четвёртый блок `error-analysis-protocol.md` — «30 нестабильных результатов из
стресс-тестов», который `error-v1-spec.md` §1 отложил формулировкой
«стресс-тесты не запускались».

Статус — **exploratory**, как и весь разбор ошибок: он идёт по оценкам
процедуры 2.

## 1. Источник

`07-analysis/stress-r5-attempts/20260731T220132Z/stress-p2a-r11-cells.csv`,
ревизия r11, попытка `20260731T220132Z`, статус прогона `completed`.

600 строк: 60 панельных документов × 10 преобразований. Преобразование t14
переведено в `not executable` амендментом r5, знаменатель — 10.

Единица отбора — **ячейка `документ × преобразование`**, а не документ. Ячейка
и есть «нестабильный результат» в терминах протокола: один текст под одним
преобразованием.

Три величины ячейки считает `stress_run_p2.aggregate` усреднением по допустимым
holdout:

| Величина | Определение |
|---|---|
| `flip_rate` | доля моделей, у которых решение пересекло порог 0.5 |
| `instability_rate` | доля моделей с \|Δp\| > 0.05 (порог задан амендментом §3 до расчёта) |
| `max_abs_delta` | наибольшее \|Δp\| по моделям ячейки |

## 2. Правило отбора

Сортировка всех 600 ячеек по четырём ключам, отсечка на тридцатой:

1. `flip_rate` по убыванию;
2. `max_abs_delta` по убыванию;
3. `document_id` по возрастанию;
4. `transform_number` по возрастанию.

Ключи 3 и 4 детерминируют результат при полном совпадении первых двух и
никакого содержательного смысла не несут.

Тай-брейк нужен фактически: на границе `flip_rate` = 0.750 стоят пять ячеек при
свободных местах менее пяти.

**Проверка после отбора, а не условие отбора.** Все 30 ячеек обязаны иметь
`flip_rate` > 0. Если правило заведёт в набор ячейку без единой смены решения,
класс `instability` наполнен не будет и отбор останавливается. Всего ячеек с
`flip_rate` > 0 в прогоне 49, поэтому запас есть; проверка страхует от ошибки
сортировки, а не от нехватки данных.

## 3. Данные, которые PI видел на момент решения

Правило журналирования §3 требует записать это отдельной строкой: агрегаты
распределения были посчитаны **до** выбора правила и предъявлены с ценой каждого
варианта. Тексты документов не открывались, карточки не составлялись.

Что было видно:

| Величина | Значение |
|---|---|
| Ячеек всего | 600 |
| `instability_rate` > 0 | 151 ячейка, 51 документ |
| `flip_rate` > 0 | 49 ячеек, 37 документов |
| `instability_rate` = 1.0 | 46 ячеек, 30 документов |
| Из них с `flip_rate` > 0 | 30 |

Плюс раскладка каждого варианта по преобразованиям, классам происхождения и
числу допустимых моделей — она приведена в §4.

## 4. Что отклонено, с числами

**Вариант B, круговой обход преобразований с квотой.** Кандидаты — 151 ячейка с
`instability_rate` > 0, внутри преобразования сортировка по убыванию
`max_abs_delta`, обход по кругу в порядке убывания числа кандидатов.

Даёт 9 преобразований из 10 (t02: 4, t03: 3, t04: 3, t05: 3, t10: 4, t11: 4,
t13: 3, t15: 2, t16: 4) и 17 машинных ячеек против 13 человеческих. Отклонён по
двум числам: 14 карточек из 30 не содержат ни одной смены решения, а наименьший
`max_abs_delta` в наборе равен 0.0503 — то есть ячейка попадает в разбор ошибок
за сдвиг вероятности на три тысячных выше порога. Документов в наборе всего 14,
и один документ даёт до четырёх карточек.

**Вариант C, пересечение `flip_rate` > 0 и `instability_rate` = 1.0.** Даёт ровно
30 ячеек без всякой отсечки. Отклонён по двум основаниям. Первое: совпадение с
квотой протокола обнаружено при просмотре распределения, то есть критерий
подогнан под нужное число задним числом. Второе — систематическое смещение:
`instability_rate` = 1.0 требует, чтобы порог перешли все допустимые модели, и
при 18 моделях это условие практически недостижимо. В варианте C ноль ячеек с
18 моделями, тогда как среди 49 ячеек с `flip_rate` > 0 таких семь. Набор
исключил бы страту RusLTC целиком.

## 5. Цена принятого правила

Записывается прямо, потому что уйдёт в текст статьи. Набор состоит из 30 ячеек:
26 приходятся на t11 (расширение текста), по остальным преобразованиям — t04: 2,
t02: 1, t05: 1. Документов 28, из них человеческих 4.

Разбор ошибок по этому блоку — разбор одного преобразования. Утверждать по нему
что-либо о сокращении текста, гомоглифах или переносе между форматами нельзя.
Основание принять такой набор: t11 и есть место, где классификатор ломается —
45.1% смен решения против 1.5% у ближайшего преобразования, и отбор по силе
эффекта ведёт именно туда. Ограничение публикуется в Limitations вместе с
нормировкой форматных признаков на объём.

> **Уточнение основания, 1 августа 2026, после отбора.** Правило и набор не
> менялись: числа 45.1% и 1.5% верны, отбор по силе эффекта остаётся в силе.
> Изменилось то, чем этот эффект объясняется. Разбор
> `stress-t10-t11-volume-defect.md` показал, что t11 — составное преобразование:
> меняет длину, дословно дублирует предложения и теряет 75.6% абзацев
> одновременно. Решение классификатора двигает дублирование, а не объём.
> Поэтому карточки блока читаются как разбор чувствительности к дословному
> повтору, а ограничение в Limitations идёт пунктом 25, отдельно от нормировки
> форматных признаков.

## 6. Что заполняет расчёт и что человек

| Поле | Кто заполняет |
|---|---|
| `case_id`, `document_id`, `transform_number`, `transform_name` | расчёт |
| `error_class` = `instability` | расчёт |
| `flip_rate`, `instability_rate`, `max_abs_delta`, `mean_delta_prob`, `n_models` | расчёт, копией из `cells.csv` |
| `flipped_splits` | расчёт: имена holdout со сменой решения, с вероятностями до и после |
| `flip_direction` | расчёт: сторона перехода, `H→A` или `A→H` |
| `origin_class`, `genre`, `prompt_condition`, `generation_channel` | расчёт, из `stress-panel-v1.csv` |
| `word_count`, `length_tertile` | расчёт, из панели и терцилей корпуса |
| `shifted_features` | расчёт: пять признаков с наибольшим \|Δz\| между исходной и преобразованной версией |
| `alternative_explanation`, `real_editorial_problem`, `conclusion` | человек, по тексту документа |
| `reviewed_by`, `reviewed_at` | человек |

**Оговорка по `shifted_features`.** Поле описывает, что преобразование сделало со
входом, а не то, что вызвало смену решения. Атрибуция решения требует
коэффициентов модели и повторного обучения — в этом блоке она не делается.
Стандартизация z берётся по 1882 документам `feature-matrix-v5.csv`.

Карточка без прочитанного текста несёт `conclusion = pending` и выводом не
считается — правило то же, что в `error-v1-spec.md` §4.
